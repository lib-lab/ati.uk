# Правила репозитория

Кликабельный прототип биржи грузоперевозок. Песочница для проверки сущностей, правил и сценариев, визуальный дизайн вторичен.

## Перед началом задачи

1. Прочитайте `docs/TZ.md` (ТЗ), `docs/PLAN.md` (утверждённый план), `docs/DECISIONS.md` (допущения), `docs/ROADMAP.md` (этапы).
2. Делайте ровно один этап из ROADMAP. Функций, которых нет в ТЗ, не добавлять. Если чего-то не хватает, предложите это отдельным списком в отчёте.

## Команды

```bash
npm install
npm run dev            # http://localhost:5173
npm test               # Vitest, все тесты
npx tsc --noEmit -p .  # проверка типов
npm run build          # типы + сборка + руководство тестировщика (docs/OVERVIEW.md → dist/guide.html, см. scripts/build-guide.mjs)
npm run build:preview  # dist/preview.html — один файл со встроенными CSS и JS для показа без сервера
```

## Архитектура

- `src/domain/` — типы, `config.ts` (все числа), чистые правила `rules/*` и команды `commands/*`. Здесь нет React, нет I/O, нет `Date.now()`: время всегда берётся из `state.now`.
- Команда — функция `(state, ...input) => CommandResult` (`{ ok: true, state } | { ok: false, error }`). Состояние иммутабельно. Id выдаются через `nextId(state, prefix)`, события пишутся через `logEvent`.
- `src/adapters/` — интерфейсы внешних систем (реестр, платежи, почта) и заглушки. Подключаются в `src/adapters/index.ts`. Домен о них не знает.
- `src/store/` — хранилище (`store.run(command)`), сохранение в localStorage, сброс.
- `src/seed/` — детерминированный сид. Если меняется форма `AppState`, поднимите `STATE_VERSION` в `src/seed/index.ts`: старые сохранённые данные тогда заменятся новым сидом.
- `src/ui/` — React. Все тексты лежат в `src/ui/i18n/en.ts` (английский, основной) и `src/ui/i18n/ru.ts` (русский, те же ключи и подстановки) и выводятся через `t(key, params)`. Новый текст добавляется в оба словаря; даты, деньги и дробные числа — через `src/ui/format.ts`, единицы — ключами `unit.*`. Регистр как в предложении.

## Соглашения

- Код и комментарии на английском, документация в `docs/` на русском, README — на английском и русском (`README.md`, `README.ru.md`).
- Деньги хранятся в центах, даты — ISO-строки в UTC.
- Каждое изменение, которое нужно объяснить (оплата, возврат, жалоба, снятие объявления, изменение рейтинга), пишется событием с `reasonKey` из i18n.
- Каждое новое правило покрывается юнит-тестом рядом с модулем (`*.test.ts`). Для тестов есть билдеры в `src/domain/testing/fixtures.ts`.
- Дизайн: плоский, без теней и градиентов; тонкие приглушённые рамки, скругления 8–12 px; системный шрифт, два начертания, основной и вторичный уровень текста. Цвет несёт смысл: акцент — только основные действия и ссылки; успех, предупреждение, опасность и нейтральное — семейства со светлой заливкой и тёмным текстом того же оттенка. Светлая и тёмная тема — через CSS-переменные. Стили лежат в `src/ui/styles.css` (подробности — DECISIONS «Визуальная полировка»).
- Дизайн-токены: все размеры в стилях — отступы, размеры шрифта, высота кнопок и полей (через внутренние отступы и высоту строки), скругления, ширина контента и колонок, толщина рамок — задаются только через CSS-переменные из `src/ui/tokens.css`. Цвета, начертания и прозрачность — тоже там. В `styles.css` и в компонентах числовых значений нет: ни `px`/`em` в правилах, ни `style={{…}}` с размерами, ни атрибутов вроде `rows`, `size`, `width`. Допустимы только `0`, `100%`, доли сетки и flex (`1fr`, `flex: 1 1 …`), номера линий сетки, множители внутри `calc()` и брейкпойнты в `@media` (переменные там не работают; список брейкпойнтов — в шапке `tokens.css`). Нужен новый размер — сначала добавьте токен. Отступы — только шкала 4 / 8 / 12 / 16 / 24 / 32 / 48 px, 5 размеров шрифта, 2 начертания; кнопки и поля не ниже 40 px (44 px на телефоне). Цвета текста держат контраст WCAG AA (4,5:1), рамки полей — 3:1, в обеих темах. Всё это проверяет `src/ui/tokens.test.ts`.
- `window.confirm/alert/prompt` не использовать: в превью они не работают. Подтверждение делается прямо на странице.

## Определение готовности этапа

- `npm test`, `npx tsc --noEmit -p .` и `npm run build` проходят.
- Критерии этапа из ROADMAP выполнены и проверены вручную в браузере.
- README на двух языках: `README.md` (английский) и `README.ru.md` (русский) — в обоих обновлены инструменты и список реализованных сценариев (с шагами проверки); содержание файлов совпадает.
- `docs/DECISIONS.md`: записаны новые допущения и отступления.
- В ROADMAP этап отмечен как сделанный.
- Один коммит (или несколько) с сообщением вида `E#: …`, затем push. В отчёте пользователю: что сделано и как проверить.
